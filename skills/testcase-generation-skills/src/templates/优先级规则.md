# 优先级规则

## 一、优先级定义

### 1.1 优先级等级说明

| 等级 | 标识 | 定义 | 典型场景 | 测试策略 | 必须覆盖 |
|------|------|------|----------|----------|----------|
| **P0（阻塞）** | P0 | 核心业务不可用，系统崩溃/数据丢失，影响系统主流程 | 无法下单、库存扣减错误、资金计算错误、数据丢失、系统崩溃 | 100%覆盖，必须验证所有场景 | 必须 |
| **P1（高）** | P1 | 重要功能受损，影响业务运行，但有规避方案或次要影响 | 主要流程报错、金额计算偏差、单据无法保存、关键字段丢失 | 100%覆盖，重点验证主场景和异常场景 | 必须 |
| **P2（中）** | P2 | 局部功能问题，有规避方案，不影响核心业务 | 非核心提示错误、次要显示问题、非关键流程报错 | 核心场景覆盖，异常场景按需选择 | 建议 |
| **P3（低）** | P3 | 体验优化或建议，不影响业务功能 | 文案优化、界面美观度建议、非必要交互改进 | 按需选择，可合并或简化 | 可选 |

### 1.2 优先级判定标准

**P0判定条件（满足任一即判定为P0）：**
- 影响核心业务主流程（如无法开单、无法收款、无法入库）
- 导致数据丢失或数据错误（如库存扣减错误、金额计算错误）
- 系统崩溃或无法启动
- 影响系统稳定性或安全性（如权限失控、数据泄露）

**P1判定条件（满足任一即判定为P1）：**
- 影响重要功能但主流程可用（如单据保存失败但可重试）
- 关键字段显示或存储错误（如金额显示错误但计算正确）
- 影响业务效率但可规避（如批量操作失败但可单条操作）
- 涉及多个模块的联动错误（如销售保存后库存未正确扣减）

**P2判定条件（满足任一即判定为P2）：**
- 仅影响局部功能（如某个查询条件失效）
- 有明确的规避方案（如可使用其他操作路径）
- 非核心提示或显示问题（如提示文案错误、图标显示异常）
- 仅影响用户体验但不影响功能（如页面加载慢但功能正常）

**P3判定条件（满足任一即判定为P3）：**
- 仅涉及文案或界面优化（如按钮文字调整、颜色优化）
- 非必要的交互改进（如增加快捷键、优化提示信息）
- 体验优化建议（如增加历史记录、优化查询速度）
- 不影响业务功能的小问题（如非关键字段显示格式）

## 二、优先级自动计算规则

### 2.1 影响维度评分表

| 影响维度 | 权重 | 评分项 | 分值 |
|---------|------|--------|------|
| **业务影响范围** | 40% | 核心业务主流程 | 10分 |
| | | 重要业务流程 | 7分 |
| | | 次要业务流程 | 4分 |
| | | 非业务功能 | 2分 |
| **数据影响程度** | 30% | 数据丢失或严重错误 | 10分 |
| | | 数据部分错误 | 7分 |
| | | 数据显示错误 | 4分 |
| | | 无数据影响 | 2分 |
| **规避方案可用性** | 20% | 无规避方案 | 10分 |
| | | 规避方案复杂 | 7分 |
| | | 规避方案简单 | 4分 |
| | | 有多种规避方案 | 2分 |
| **用户影响面** | 10% | 所有用户 | 10分 |
| | | 大部分用户 | 7分 |
| | | 部分用户 | 4分 |
| | | 特定用户 | 2分 |

### 2.2 优先级计算公式

**总分 = 业务影响范围分 × 40% + 数据影响程度分 × 30% + 规避方案可用性分 × 20% + 用户影响面分 × 10%**

**优先级判定阈值：**
- 总分 ≥ 8.0 → P0
- 总分 ≥ 6.0 → P1
- 总分 ≥ 4.0 → P2
- 总分 < 4.0 → P3

### 2.3 计算示例

**示例1：销售单保存失败**
- 业务影响范围：核心业务主流程（10分）
- 数据影响程度：数据部分错误（7分）
- 规避方案可用性：无规避方案（10分）
- 用户影响面：所有用户（10分）

总分 = 10×0.4 + 7×0.3 + 10×0.2 + 10×0.1 = 4.0 + 2.1 + 2.0 + 1.0 = 9.1分 → **P0**

**示例2：库存查询页面加载慢**
- 业务影响范围：次要业务流程（4分）
- 数据影响程度：无数据影响（2分）
- 规避方案可用性：有多种规避方案（2分）
- 用户影响面：部分用户（4分）

总分 = 4×0.4 + 2×0.3 + 2×0.2 + 4×0.1 = 1.6 + 0.6 + 0.4 + 0.4 = 3.0分 → **P3**

## 三、特殊场景优先级调整

### 3.1 自动升级规则

**规则1：涉及金额或库存 → 自动升级**
- 凡涉及金额计算、金额显示、金额存储 → 优先级至少为P1
- 凡涉及库存扣减、库存入库、库存调整 → 优先级至少为P1
- 凡涉及库存数量错误、库存数据丢失 → 自动升级为P0

**规则2：涉及状态流转 → 自动升级**
- 凡涉及单据状态流转（如销售单状态、进货单状态） → 优先级至少为P1
- 凡涉及状态流转错误导致流程中断 → 自动升级为P0

**规则3：涉及跨模块联动 → 自动升级**
- 凡涉及跨模块联动（如销售-库存联动、销售-资金联动） → 优先级至少为P1
- 凡涉及联动数据错误 → 自动升级为P0

**规则4：涉及多端同步 → 自动升级**
- 凡涉及多端数据同步（如PC端和APP端数据同步） → 优先级至少为P1
- 凡涉及同步数据不一致 → 自动升级为P0

**规则5：涉及多店场景 → 自动升级**
- 凡涉及多店数据同步、多店权限 → 优先级至少为P1
- 凡涉及多店数据错误 → 自动升级为P0

### 3.2 自动降级规则

**规则1：仅涉及UI优化 → 自动降级**
- 仅涉及界面样式、颜色、布局调整 → 优先级最高为P3

**规则2：仅涉及文案调整 → 自动降级**
- 仅涉及提示文案、按钮文字、标签文字调整 → 优先级最高为P3

**规则3：仅涉及非核心交互 → 自动降级**
- 仅涉及快捷键、鼠标交互、键盘交互等非核心交互 → 优先级最高为P2

## 四、优先级分布要求

### 4.1 最小覆盖要求

| 优先级 | 最小数量要求 | 说明 |
|--------|-------------|------|
| P0 | 至少1个 | 核心业务主流程必须有P0测试点 |
| P1 | 至少5个 | 重要业务场景必须有P1测试点 |
| P2 | 至少10个 | 局部功能场景建议有P2测试点 |
| P3 | 最多20个 | 低优先级测试点数量限制 |

### 4.2 优先级分布校验规则

**校验规则1：P0必须覆盖主流程**
- 每个需求必须至少有1个P0测试点覆盖核心主流程

**校验规则2：P1必须覆盖关键分支**
- 每个需求必须至少有5个P1测试点覆盖关键业务分支

**校验规则3：P3数量限制**
- P3测试点数量不超过总测试点数量的20%
- P3测试点总数不超过20个

**校验规则4：优先级分布合理性**
- P0+P1测试点数量 ≥ 总测试点数量的50%
- P2+P3测试点数量 ≤ 总测试点数量的50%

## 五、优先级人工调整机制

### 5.1 人工调整场景

**场景1：自动计算结果与实际情况不符**
- 当自动计算结果与测试工程师经验判断不符时，允许人工调整
- 调整后需记录调整原因和调整依据

**场景2：业务特殊要求**
- 某些业务场景有特殊重要性要求，允许人工调整优先级
- 调整后需记录业务特殊要求说明

**场景3：历史缺陷频发**
- 某些场景历史缺陷频发，建议人工提升优先级
- 调整后需关联历史缺陷记录

### 5.2 人工调整记录要求

**记录内容：**
- 原优先级（自动计算结果）
- 调整后优先级
- 调整原因（如"历史缺陷频发"、"业务特殊要求"、"与经验判断不符"）
- 调整依据（如"关联缺陷BUG-001"、"业务方明确要求"）
- 调整人
- 调整时间

## 六、优先级与测试深度关联

### 6.1 测试深度定义

| 测试深度 | P0覆盖 | P1覆盖 | P2覆盖 | P3覆盖 |
|---------|--------|--------|--------|--------|
| **完整覆盖** | 100%主场景+100%异常场景 | 100%主场景+80%异常场景 | 100%主场景+50%异常场景 | 50%主场景 |
| **核心流程覆盖** | 100%主场景+50%关键异常 | 100%主场景+30%关键异常 | 100%主场景 | 按需选择 |
| **快速验证** | 100%主场景 | 80%主场景 | 按需选择 | 不覆盖 |

### 6.2 测试深度自动匹配

**规则：**
- 测试深度为"完整覆盖" → P0-P3均需覆盖（按上述比例）
- 测试深度为"核心流程覆盖" → P0-P2必须覆盖，P3按需选择
- 测试深度为"快速验证" → P0-P1必须覆盖，P2-P3按需选择

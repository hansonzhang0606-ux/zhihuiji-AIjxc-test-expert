# 隐性需求挖掘规则

## 文档说明
- 用途：阶段1需求点提取时的隐性需求识别
- 适用范围：从需求文档中挖掘未明确表述的隐性需求
- 调用阶段：阶段1 - Step 1.4：质量管控

---

## 一、隐性需求定义

### 1.1 什么是隐性需求

**定义：** 隐性需求是指需求文档中未明确表述，但根据业务逻辑、系统特性、历史经验等推断出的必要测试点。

**特征：**
- 未在需求文档中明确写出
- 但基于业务逻辑必然存在
- 如不测试可能导致遗漏重要场景
- 通常涉及状态流转、数据联动、权限控制等

**示例：**
```
显性需求：销售单新增审核功能，审核通过后销售单状态变为"已审核"

隐性需求：
- 审核拒绝后销售单状态是什么？
- 审核中途是否可以撤回？
- 审核后库存是否扣减？
- 审核后资金是否生成收款？
- 审核权限是否需要控制？
```

---

## 二、隐性需求分类

### 2.1 状态流转隐性需求

**定义：** 涉及单据或数据状态流转时，未明确表述的状态变化场景。

**识别触发条件：**
- 需求文档提到"状态变更"、"状态流转"、"状态改变"
- 需求文档提到单据的"审批"、"审核"、"确认"等操作
- 需求文档提到数据的"启用"、"禁用"、"发布"、"下架"等操作

**隐性需求识别规则：**

| 规则编号 | 规则名称 | 识别条件 | 隐性需求内容 |
|---------|---------|----------|------------|
| SR-001 | 前置状态 | 需求提到状态变更，但未说明前置状态 | 前置状态是什么？哪些状态可以执行该操作？ |
| SR-002 | 后置状态 | 需求提到状态变更，但未说明后置状态 | 后置状态是什么？状态变更后的数据变化？ |
| SR-003 | 状态流转路径 | 需求提到状态变更，但未说明流转路径 | 状态流转路径是什么？是否有中间状态？ |
| SR-004 | 状态逆向操作 | 需求提到状态变更，但未说明逆向操作 | 是否可以逆向操作？逆向操作的条件？ |
| SR-005 | 状态并发冲突 | 需求提到状态变更，但未说明并发场景 | 多人同时操作是否冲突？如何处理？ |

**挖掘示例：**
```
需求：销售单新增审核功能，审核通过后销售单状态变为"已审核"

隐性需求识别：
1. SR-001 前置状态：
   - 需求提到"审核通过后状态变为已审核"
   - 隐性需求：前置状态是什么？只有"待审核"状态才能审核吗？

2. SR-004 状态逆向操作：
   - 需求提到"审核通过"
   - 隐性需求：审核拒绝后状态是什么？是否可以撤回审核？

3. SR-005 状态并发冲突：
   - 需求提到"审核"
   - 隐性需求：多人同时审核同一单据如何处理？
```

---

### 2.2 数据联动隐性需求

**定义：** 涉及数据联动时，未明确表述的联动影响范围。

**识别触发条件：**
- 需求文档提到"保存"、"提交"、"确认"等操作
- 需求文档涉及多个业务模块（如销售、库存、资金）
- 需求文档涉及数据计算或汇总

**隐性需求识别规则：**

| 规则编号 | 规则名称 | 识别条件 | 隐性需求内容 |
|---------|---------|----------|------------|
| DR-001 | 库存联动 | 需求涉及销售、进货、盘点等操作 | 是否影响库存？库存如何变化？ |
| DR-002 | 资金联动 | 需求涉及销售、进货、收款、付款等操作 | 是否影响资金？资金如何变化？ |
| DR-003 | 统计联动 | 需求涉及数据保存或变更 | 是否影响统计数据？统计如何更新？ |
| DR-004 | 历史联动 | 需求涉及数据变更 | 是否影响历史记录？历史如何记录？ |
| DR-005 | 关联数据联动 | 需求涉及单据操作 | 是否影响关联单据？关联单据如何处理？ |
| DR-006 | 可信数据联动 | 需求涉及销售单和进货单列表操作 | 单条数据中数据和折扣会根据用户点击到的输入框作为可信数据，其他的数据或折扣都通过可信数据进行换算，前端四舍五入取前两位小数展示 |
| **DR-007** | **进货价反写** | **需求涉及进货单保存** | **开进货单时输入的进货价会反写到商品进货价栏** |

**挖掘示例：**
```
需求：销售单保存时自动扣减库存

隐性需求识别：
1. DR-001 库存联动：
   - 需求提到"扣减库存"
   - 隐性需求：扣减哪个仓库的库存？扣减数量如何计算？

2. DR-002 资金联动：
   - 需求涉及销售保存
   - 隐性需求：是否生成应收款？资金流水如何记录？

3. DR-003 统计联动：
   - 需求涉及销售保存
   - 隐性需求：销售统计是否更新？热销统计是否更新？

```

### 2.3 权限控制隐性需求

**定义：** 涉及权限相关操作时，未明确表述的权限控制规则。

**识别触发条件：**
- 需求文档提到"操作"、"修改"、"删除"等动作
- 求文档涉及敏感操作（如系统初始化、数据清空）
- 需求文档涉及多人协作场景

**隐性需求识别规则：**

| 规则编号 | 规则名称 | 识别条件 | 隐性需求内容 |
|---------|---------|----------|------------|
| PR-001 | 角色权限 | 需求涉及功能操作 | 哪些角色可以操作？权限如何控制？ |
| PR-002 | 操作权限 | 需求涉及敏感操作 | 是否需要特殊权限？如何授权？ |
| PR-003 | 数据权限 | 需求涉及数据查看或修改 | 数据权限范围？哪些数据可见？ |
| PR-004 | 并发权限 | 需求涉及多人协作 | 多人同时操作权限如何处理？ |

**挖掘示例：**
```
需求：老板可以在进销存软件版本降级后（比如从多店版本降级到单店版本），重新选择仍可用的门店，同时分配哪些员工的账号仍可用

隐性需求识别：
1. PR-001 角色权限：
   - 需求提到"老板可以重新分配员工账号权限"
   - 隐性需求：员工账号是否可以查看？其他角色是否可以查看？

2. PR-003 数据权限：
   - 需求提到"员工账号仍可正常使用"
   - 隐性需求：可用员工可以看到所有门店的数据吗？还是仅该员工绑定门店的？
```

### 2.4 异常处理隐性需求

**定义：** 涉及异常场景时，未明确表述的异常处理逻辑。

**识别触发条件：**
- 求文档提到数据输入、保存、计算等操作
- 需求文档涉及外部依赖（如接口调用、网络请求）
- 需求文档涉及边界条件（如最大值、最小值、特殊值）

**隐性需求识别规则：**

| 规则编号 | 规则名称 | 识别条件 | 隐性需求内容 |
|---------|---------|----------|------------|
| ER-001 | 输入异常 | 需求涉及数据输入 | 输入异常值如何处理？如负数、超限值 |
| ER-002 | 操作异常 | 需求涉及数据保存或提交 | 操作失败如何处理？是否可以重试？ |
| ER-003 | 边界异常 | 求涉及数值计算 | 边界值如何处理？如最大库存、最小库存 |
| ER-004 | 外部异常 | 需求涉及外部依赖 | 外部依赖失败如何处理？如接口失败 |
| ER-005 | 并发异常 | 需求涉及并发操作 | 并发冲突如何处理？如库存同时扣减 |
| **ER-006** | **负库存特殊场景** | **需求涉及进货单保存且当前库存为负** | **当负库存进行进货时，成本价等于进货价（而非移动加权计算）** |

**挖掘示例：**
```
需求：销售单保存时计算销售金额

隐性需求识别：
1. ER-001 输入异常：
   - 需求涉及金额计算
   - 隐性需求：输入负数金额如何处理？输入超大金额如何处理？计算后有多位小数，但前端显示只四舍五入保留2位，计算是否准确？

2. ER-003 边界异常：
   - 需求涉及金额计算
   - 隐性需求：金额最大值是多少？超出如何处理？

3. ER-005 并发异常：
   - 求涉及销售保存
   - 隐性需求：多人同时保存同一单据如何处理？
```

### 2.5 业务规则隐性需求

**定义：** 涉及业务判断时，未明确表述的业务规则细节。

**识别触发条件：**
- 需求文档提到"判断"、"条件"、"规则"等关键词
- 需求文档涉及业务逻辑复杂的场景
- 需求文档涉及历史业务模式

**隐性需求识别规则：**

| 规则编号 | 规则名称 | 识别条件 | 隐性需求内容 |
|---------|---------|----------|------------|
| BR-001 | 判断条件细节 | 需求涉及条件判断 | 判断条件细节是什么？边界条件？ |
| BR-002 | 规则优先级 | 需求涉及多规则 | 规则优先级如何？冲突如何处理？ |
| BR-003 | 历史规则继承 | 需求涉及功能变更 | 是否继承历史规则？历史规则如何处理？ |
| **BR-004** | **成本价计算规则** | **需求涉及进货单保存、成本价计算** | **成本价采用移动加权方式进行计算，目前仅开进货单会影响成本价** |
| **BR-005** | **报价管理规则** | **需求涉及销售单新增或修改、报价取值** | **报价取值规则：<br>1. 新增销售单时，当前单据为最新一笔单据（没有未来单），客户的报价取当前的报价<br>2. 新增历史单据时，当该商品在客户名下没有任何报价时，客户报价取该单的报价<br>3. 修改单据时，当该商品在客户名下没有任何报价时，客户报价取该单的报价** |
| **BR-006** | **销售统计查询规则** | **需求涉及销售统计报告、按商品统计查询** | **销售统计报告-按商品统计中，如果同时使用商品名称和分类进行查询时，查询出的结果取两者的并集数据** |

**挖掘示例：**
```
需求：新用户首单保存后弹窗

隐性需求识别：
1. BR-001 判断条件细节：
   - 需求提到"新用户首单"
   - 隐性需求：新用户定义是什么？首单定义是什么？

2. BR-002 规则优先级：
   - 需求提到"弹窗"
   - 隐性需求：如果有多个弹窗，优先级如何？
```

**进销存特定业务规则挖掘示例：**
```
需求1：进货单保存功能

隐性需求识别：
1. DR-007 进货价反写：
   - 需求涉及进货单保存
   - 隐性需求：开进货单时输入的进货价会反写到商品进货价栏

需求2：成本价计算功能

隐性需求识别：
1. BR-004 成本价计算规则：
   - 需求涉及成本价计算
   - 隐性需求：成本价采用移动加权方式进行计算，目前仅开进货单会影响成本价

2. ER-006 负库存特殊场景：
   - 需求涉及进货和成本价计算
   - 隐性需求：当负库存进行进货时，成本价等于进货价（而非移动加权计算）

需求3：销售单报价功能

隐性需求识别：
1. BR-005 报价管理规则：
   - 求涉及销售单报价取值
   - 隐性需求：
     - 新增销售单时，当前单据为最新一笔单据（没有未来单），客户的报价取当前的报价
     - 新增历史单据时，当该商品在客户名下没有任何报价时，客户报价取该单的报价
     - 修改单据时，当该商品在客户名下没有任何报价时，客户报价取该单的报价

需求4：销售统计报告功能

隐性需求识别：
1. BR-006 销售统计查询规则：
   - 需求涉及销售统计报告-按商品统计查询
   - 隐性需求：如果同时使用商品名称和分类进行查询时，查询出的结果取两者的并集数据
```

## 三、隐性需求挖掘流程

### 3.1 挖掘执行流程

```
需求文档分析 → 隐性需求类型识别 → 应用识别规则 → 
生成隐性需求清单 → 输出到待确认清单
```

### 3.2 挖掘执行步骤

**Step 1：需求文档分析**
- 读取需求文档内容
- 提取关键词和业务场景

**Step 2：隐性需求类型识别**
- 根据关键词判断隐性需求类型
- 状态流转关键词：状态、审批、审核、启用、禁用
- 数据联动关键词：保存、提交、扣减、增加、计算
- 权限控制关键词：操作、查看、修改、删除
- 异常处理关键词：输入、保存、计算、接口

**Step 3：应用识别规则**
- 对识别的类型应用对应的识别规则
- 每个规则生成对应的隐性需求问题

**Step 4：生成隐性需求清单**
- 将所有隐性需求整理为清单
- 每个隐性需求包含：问题描述、识别来源、影响范围

**Step 5：输出到待确认清单**
- 将隐性需求清单输出到待确认清单
- 用户确认后转化为正式需求点

## 四、隐性需求验证策略

### 4.1 验证方式

**验证方式1：用户确认**
- 将隐性需求清单输出给用户
- 用户逐项确认或澄清
- 确认后转化为正式需求点

**验证方式2：历史经验参考**
- 参考历史知识库（templates/history_cases.json）
- 参考历史缺陷模式（templates/history_bugs.json）
- 基于历史经验推断隐性需求合理性

**验证方式3：业务逻辑推断**
- 根据进销存业务逻辑推断
- 基于业务常识判断隐性需求必要性

### 4.2 验证优先级

| 验证方式 | 优先级 | 适用场景 | 可信度 |
|---------|--------|----------|--------|
| 用户确认 | 最高 | 所有隐性需求 | 100% |
| 历史经验参考 | 中 | 有历史知识库时 | 80% |
| 业务逻辑推断 | 低 | 无法确认时 | 60% |

### 4.3 验证流程

```
隐性需求清单 → 验证方式选择 → 
用户确认 → 确认的需求点 → 加入需求点清单
          ↓
        用户否认 → 否认的需求点 → 记录但不加入需求点清单
          ↓
        用户不确定 → 待确认需求点 → 保留在待确认清单
```

## 五、隐性需求输出格式

### 5.1 隐性需求清单格式

**隐性需求清单包含：**
- 隐性需求ID
- 隐性需求类型
- 问题描述
- 识别来源（需求文档位置）
- 影响范围（涉及的测试场景）
- 建议澄清问题

**格式示例：**
```
隐性需求 IR-001：
  - 类型：状态流转隐性需求（SR-001）
  - 问题：前置状态是什么？
  - 来源：需求文档第3节第2段
  - 影响范围：销售单审核流程测试点提取
  - 建议澄清问题："待审核"状态才能审核吗？其他状态是否可以审核？
```

### 5.2 待确认清单整合

**隐性需求整合到待确认清单：**
- 隐性需求ID改为待确认ID格式（如IR-001改为BC-001或CC-001）
- 添加到待确认清单中
- 与其他待确认项一起等待用户确认

## 六、隐性需求挖掘示例

### 6.1 完整示例

**需求内容：**
```
销售单新增审核功能：
1. 销售单保存后可以提交审核
2. 审核通过后销售单状态变为"已审核"
3. 审核通过后库存自动扣减
```

**隐性需求挖掘：**

**类型1：状态流转隐性需求**
```
IR-001：
  - 类型：状态流转隐性需求（SR-001）
  - 问题：前置状态是什么？
  - 来源：需求第2点
  - 影响：审核操作前置条件测试
  - 建议：只有"待审核"状态才能审核吗？

IR-002：
  - 类型：状态流转隐性需求（SR-004）
  - 问题：审核拒绝后状态是什么？
  - 来源：需求第2点
  - 影响：审核拒绝流程测试
  - 建议：审核拒绝后状态是"已拒绝"还是"待审核"？

IR-003：
  - 类型：状态流转隐性需求（SR-004）
  - 问题：是否可以撤回审核？
  - 来源：需求第2点
  - 影响：审核撤回流程测试
  - 建议：审核后是否可以撤回？撤回条件是什么？
```

**类型2：数据联动隐性需求**
```
IR-004：
  - 类型：数据联动隐性需求（DR-001）
  - 问题：扣减哪个仓库的库存？
  - 来源：需求第3点
  - 影响：库存扣减测试
  - 建议：扣减哪个仓库的库存？销售单关联仓库？

IR-005：
  - 类型：数据联动隐性需求（DR-002）
  - 问题：是否生成应收款？
  - 来源：需求第3点
  - 影响：资金流水测试
  - 建议：审核通过后是否生成应收款？收款流程？

IR-006：
  - 类型：数据联动隐性需求（DR-003）
  - 问题：统计是否更新？
  - 来源：需求第3点
  - 影响：销售统计测试
  - 建议：审核通过后销售统计是否更新？
```

**类型3：权限控制隐性需求**

## 七、隐性需求与需求质量的关联

### 7.1 质量等级与隐性需求

| 需求质量等级 | 隐性需求特点 | 隐性需求数量 | 处理方式 |
|-------------|-------------|-------------|----------|
| A级 | 隐性需求少，大部分已明确 | 少量（<5项） | 直接补充到需求点清单 |
| B级 | 隐性需求适中，部分需确认 | 中等（5-10项） | 输出到待确认清单，用户确认 |
| C级 | 隐性需求多，大量需确认 | 较多（10-20项） | 输出到待确认清单，用户大量确认 |
| D级 | 隐性需求无法识别 | 无法识别 | 无法处理，需求文档不合格 |

### 7.2 隐性需求数量阈值

**隐性需求数量判定：**
- 隐性需求 < 5项 → 需求质量较好，可直接补充
- 隐性需求 5-10项 → 需求质量一般，需用户确认
- 隐性需求 10-20项 → 求求质量较差，需大量确认
- 隐性需求 > 20项 → 需求质量很差，可能为D级

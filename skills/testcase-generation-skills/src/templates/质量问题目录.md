# 需求质量问题分级规则

## 文档说明
- 用途：阶段1需求点提取时的质量管控
- 适用范围：需求文档质量判定和处理策略
- 调用阶段：阶段1 - Step 1.4：质量管控

---

## 一、质量问题分级定义

### 1.1 分级标准

| 等级 | 标识 | 定义 | 判定条件 | 典型特征 |
|------|------|------|----------|----------|
| **A级（优秀）** | A | 需求描述完整、逻辑清晰、无歧义，可直接提取测试点 | 需求文档包含完整的功能描述、业务规则、验收标准、异常场景 | • 功能描述完整<br>• 业务规则明确<br>• 验收标准清晰<br>• 异常场景覆盖<br>• 无歧义表述 |
| **B级（良好）** | B | 需求描述基本完整、逻辑基本清晰、存在少量歧义，需澄清后提取测试点 | 需求文档包含主要功能描述和业务规则，但缺少部分验收标准或异常场景 | • 功能描述基本完整<br>• 业务规则基本明确<br>• 验收标准部分缺失<br>• 异常场景覆盖不全<br>• 存在少量歧义表述 |
| **C级（一般）** | C | 需求描述不完整、逻辑不清晰、存在较多歧义，需大量澄清后才能提取测试点 | 求文档仅包含基础功能描述，缺少业务规则、验收标准、异常场景 | • 功能描述不完整<br>• 业务规则缺失<br>• 验收标准缺失<br>• 异常场景缺失<br>• 存在较多歧义表述 |
| **D级（不合格）** | D | 需求描述严重不完整、逻辑混乱、无法理解，无法提取测试点 | 需求文档功能描述模糊、逻辑混乱、无法理解业务意图 | • 功能描述严重缺失或模糊<br>• 逻辑混乱或相互矛盾<br>• 无法理解业务意图<br>• 缺乏必要的上下文信息 |

## 二、分级判定规则

### 2.1 判定维度

| 判定维度 | 权重 | 评分项 | 分值 | 说明 |
|---------|------|--------|------|------|
| **功能描述完整性** | 30% | 完整（包含功能目标、用户操作、系统响应） | 10分 | 能清楚描述功能要做什么、用户如何操作、系统如何响应 |
| | | 基本完整（包含功能目标、部分操作） | 7分 | 能描述功能目标，但操作步骤或系统响应不完整 |
| | | 不完整（仅有功能目标） | 4分 | 仅描述功能目标，缺少操作步骤和系统响应 |
| | | 严重缺失或模糊 | 2分 | 功能描述模糊，无法理解要做什么 |
| **业务规则明确性** | 25% | 明确（包含所有业务规则、条件判断） | 10分 | 业务规则清晰，包含所有条件判断和触发规则 |
| | | 基本明确（包含主要业务规则） | 7分 | 包含主要业务规则，但部分条件判断缺失 |
| | | 不明确（仅部分业务规则） | 4分 | 仅包含部分业务规则，条件判断缺失 |
| | | 严重缺失 | 2分 | 业务规则缺失，无法判断功能如何执行 |
| **验收标准清晰性** | 20% | 清晰（包含明确验收标准） | 10分 | 验收标准明确，可直接用于测试点提取 |
| | | 基本清晰（包含部分验收标准） | 7分 | 包含部分验收标准，需补充其他验收标准 |
| | | 不清晰（验收标准缺失） | 4分 | 验收标准缺失，需用户澄清 |
| | | 严重缺失 | 2分 | 无法判断功能是否完成 |
| **异常场景覆盖性** | 15% | 覆盖（包含所有异常场景） | 10分 | 异常场景覆盖完整，包含边界条件、异常输入、错误处理 |
| | | 基本覆盖（包含主要异常场景） | 7分 | 包含主要异常场景，但边界条件或错误处理缺失 |
| | | 不覆盖（仅少量异常场景） | 4分 | 仅包含少量异常场景，需补充 |
| | | 严重缺失 | 2分 | 异常场景完全缺失 |
| **表述清晰度** | 10% | 清晰（无歧义表述） | 10分 | 表述清晰，无歧义，可直接理解 |
| | | 基本清晰（存在少量歧义） | 7分 | 存在少量歧义表述，需澄清 |
| | | 不清晰（存在较多歧义） | 4分 | 存在较多歧义表述，需大量澄清 |
| | | 严重模糊 | 2分 | 表述严重模糊，无法理解 |

### 2.2 分级判定公式

**总分 = 功能描述完整性分 × 30% + 业务规则明确性分 × 25% + 验收标准清晰性分 × 20% + 异常场景覆盖性分 × 15% + 表述清晰度分 × 10%**

**分级判定阈值：**
- 总分 ≥ 8.5 → A级（优秀）
- 总分 ≥ 7.0 → B级（良好）
- 总分 ≥ 4.5 → C级（一般）
- 总分 < 4.5 → D级（不合格）

### 2.3 判定示例

**示例1：A级需求**
- 功能描述完整性：完整（10分）
- 业务规则明确性：明确（10分）
- 验收标准清晰性：清晰（10分）
- 异常场景覆盖性：覆盖（10分）
- 表述清晰度：清晰（10分）

总分 = 10×0.3 + 10×0.25 + 10×0.2 + 10×0.15 + 10×0.1 = 3.0 + 2.5 + 2.0 + 1.5 + 1.0 = 10.0分 → **A级**

**示例2：B级需求**
- 功能描述完整性：基本完整（7分）
- 业务规则明确性：基本明确（7分）
- 验收标准清晰性：基本清晰（7分）
- 异常场景覆盖性：基本覆盖（7分）
- 表述清晰度：基本清晰（7分）

总分 = 7×0.3 + 7×0.25 + 7×0.2 + 7×0.15 + 7×0.1 = 2.1 + 1.75 + 1.4 + 1.05 + 0.7 = 7.0分 → **B级**

## 三、处理策略

### 3.1 A级处理策略

**处理方式：**
- 直接提取测试点，无需澄清
- 按100%覆盖率提取需求点
- 自动进入阶段1后续步骤

**输出：**
- 需求点清单（完整性100%）
- 无待确认问题

**处理流程：**
```
A级需求 → 直接提取需求点 → 输出需求点清单 → 进入Step 1.5
```

---

### 3.2 B级处理策略

**处理方式：**
- 提取可明确的需求点
- 识别歧义部分，生成待确认清单
- 用户确认后补充需求点

**输出：**
- 需求点清单（完整性80%）
- 待确认问题清单（包含需澄清的歧义部分）

**处理流程：**
```
B级需求 → 提取明确需求点 → 识别歧义部分 → 输出需求点清单 + 待确认清单 → 用户确认 → 补充需求点
```

**待确认清单示例：**
```
待确认项 BC-001：
  - 问题：需求描述中提到"销售单保存成功后触发"，但未明确是否包含"保存并打印"路径
  - 来源：需求文档第3节第2段
  - 影响范围：销售单保存流程测试点提取
  - 建议澄清问题："保存并打印"路径是否也触发该功能？
```

---

### 3.3 C级处理策略

**处理方式：**
- 仅提取基础功能需求点
- 生成大量待确认清单
- 要求用户补充需求文档或澄清问题

**输出：**
- 需求点清单（完整性40%）
- 待确认问题清单（包含缺失的业务规则、验收标准、异常场景）

**处理流程：**
```
C级需求 → 提取基础需求点 → 识别缺失内容 → 输出需求点清单 + 大量待确认清单 → 
用户补充需求文档或澄清 → 补充需求点 → 重新质量评估
```

**待确认清单示例：**
```
待确认项 CC-001：
  - 问题：需求描述缺少业务规则，未明确触发条件和判断规则
  - 来源：需求文档第2节
  - 影响范围：业务规则测试点提取
  - 建议补充内容：请补充业务规则描述，包括触发条件、判断规则、执行逻辑

待确认项 CC-002：
  - 问题：需求描述缺少验收标准，无法判断功能完成标准
  - 来源：需求文档第3节
  - 影响范围：验收标准测试点提取
  - 建议补充内容：请补充验收标准，包括功能完成标准、数据验证标准、界面验证标准

待确认项 CC-003：
  - 问题：需求描述缺少异常场景，未明确异常输入和错误处理
  - 来源：需求文档第4节
  - 影响范围：异常场景测试点提取
  - 建议补充内容：请补充异常场景，包括边界条件、异常输入、错误处理逻辑
```

**用户响应选项：**
```
AI: 需求文档质量评估为C级（一般），存在以下问题：
    - 业务规则缺失
    - 验收标准缺失
    - 异常场景缺失
    
    已生成待确认清单（共3项），请选择处理方式：
    [1] 补充需求文档（重新上传或提供补充文档）
    [2] 直接澄清问题（逐项回答待确认问题）
    [3] 按现有内容提取（仅提取基础需求点，后续人工补充）
```

---

### 3.4 D级处理策略

**处理方式：**
- 无法提取需求点
- 输出质量不合格报告
- 要求用户重新提供需求文档

**输出：**
- 需求点清单（空）
- 质量不合格报告（包含问题描述、改进建议）
- 阻塞后续流程

**处理流程：**
```
D级需求 → 无法提取需求点 → 输出质量不合格报告 → 阻塞流程 → 
用户重新提供需求文档 → 重新质量评估
```

**质量不合格报告示例：**
```
质量不合格报告 QNR-001：
  - 评估等级：D级（不合格）
  - 问题描述：
    1. 功能描述严重缺失：仅提到"优化销售流程"，未描述具体优化内容
    2. 逻辑混乱：提到"保存后自动审核"，但又提到"手动审核"，逻辑矛盾
    3. 无法理解业务意图：无法判断功能目标是什么，要实现什么效果
    
  - 影响范围：无法提取任何测试点，阻塞测试用例生成流程
  
  - 改进建议：
    1. 请重新编写需求文档，明确功能目标和业务意图
    2. 请补充完整的功能描述，包括用户操作、系统响应、业务规则
    3. 请检查逻辑一致性，消除矛盾表述
    4. 请补充验收标准和异常场景
    
  - 参考模板：
    需求文档建议包含以下内容：
    - 功能目标：明确描述要实现什么功能
    - 用户操作：描述用户如何操作
    - 系统响应：描述系统如何响应
    - 业务规则：描述业务判断规则
    - 验收标准：描述功能完成标准
    - 异常场景：描述异常情况处理
```

**用户响应：**
```
AI: 需求文档质量评估为D级（不合格），无法提取需求点。
    
    问题：
    - 功能描述严重缺失
    - 逻辑混乱
    - 无法理解业务意图
    
    已生成质量不合格报告，请重新提供需求文档或澄清需求内容。
    
    [1] 重新上传需求文档
    [2] 与产品经理沟通澄清（暂停生成，等待沟通）
    [3] 跳过此需求（放弃生成）
```

## 五、特殊情况处理

### 5.1 多需求混合文档

**情况：** 一个需求文档包含多个独立小需求（如周迭代文档）

**处理策略：**
- 对每个小需求独立进行质量评估
- 每个小需求单独生成需求点清单和待确认清单
- 按小需求拆分输出多份产物

**处理流程：**
```
多需求文档 → 需求拆分 → 每个小需求独立评估 → 
生成多份需求点清单 + 多份待确认清单（如有）
```

### 5.2 需求文档格式多样

**情况：** 需求文档格式多样（Confluence、Markdown、Word）

**处理策略：**
- 不因格式差异影响质量评估
- 仅评估内容质量，不评估格式质量
- 对所有格式采用统一的评估标准

### 5.3 需求文档更新

**情况：** 用户补充或更新需求文档后重新评估

**处理策略：**
- 重新进行质量评估
- 如等级提升，更新需求点清单
- 如仍为低等级，继续要求补充

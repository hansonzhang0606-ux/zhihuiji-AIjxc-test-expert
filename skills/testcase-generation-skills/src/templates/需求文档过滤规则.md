# 需求文档内容过滤规则（1A 前置 · 硬过滤）

> 用途：Stage1A **提取需求点之前**，用脚本从 Markdown **物理剔除**无测试价值章节，避免 LLM 再读到「需求背景」原文。  
> 脚本：`scripts/stage1/filter_requirement_doc.js`  
> 产物：`script/stage1/requirement_filtered.md`（**1A 唯一正文输入**）

---

## 一、为什么不用「只靠 Prompt 过滤」

实践中仅靠 Prompt 划「保留区」会失败：模型仍把「一、需求背景」下的 **1.1 核心规则 / 1.2 现状问题** 标成保留区并抽成 RP（如「现状问题: …」）。

**硬约束：**
1. 必须先跑过滤脚本，写出 `requirement_filtered.md`  
2. 1A LLM **禁止**再读 `input/需求文档/{title}.md` 原文  
3. 命中过滤标题 → **整棵子树删除**（含子节，**不再**对「核心规则/现状问题」开例外）

---

## 二、保留 / 过滤对照表

| 内容类型 | 是否保留 | 说明 | 常见标题关键词 |
|----------|----------|------|----------------|
| 设计逻辑 | ✓ | 须在**非背景章**下 | 设计逻辑、实现逻辑、方案设计、处理逻辑 |
| 功能描述 | ✓ | | 功能说明、功能描述、交互说明 |
| 业务规则 | ✓ | 须在**非背景章**下 | 业务规则、规则说明、计算规则 |
| 前置/后置条件 | ✓ | | 前置条件、验收标准、预期结果 |
| 输入输出 | ✓ | | 输入、输出、字段说明 |
| 埋点/统计 | ✓ | | 埋点、上报、曝光 |
| 界面设计 | ✓ | | 界面、UI、原型、文案 |
| 异常/边界 | ✓ | | 异常、边界、上限、长度限制 |
| 场景/流程 | ✓ | | 场景、流程、步骤、弹窗规则 |
| 非目标 | ✓（边界） | | 非目标、不在范围 |
| **需求背景** | ✗ **整章剔除** | 含其下任意子节 | 需求背景、背景介绍、为什么做 |
| **市场调研** | ✗ | | 市场调研、用户调研 |
| **竞品分析** | ✗ | | 竞品、对标 |
| **ROI** | ✗ | | ROI、投入产出 |
| **项目背景** | ✗ | | 项目背景、立项背景 |
| **未来规划** | ✗ | | 未来规划、Roadmap、展望 |
| **历史版本说明** | ✗（默认） | 标题含「本期仍生效/需回归/与本期差异」则保留 | 历史版本、往期 |

### 2.1 与旧版差异（重要）

| 旧版（已废弃） | 现版（强制） |
|----------------|--------------|
| 「需求背景」下的核心规则/现状问题可保留抽点 | **一律随父章删除**，不得抽成 RP |
| 仅 Prompt 约定过滤 | **脚本物理删除**后再喂 LLM |

文档作者若把可测规则写在「需求背景」下：应改到「设计逻辑 / 业务规则 / 场景」等独立章节；否则过滤后 1A 看不到这些句。

## 三、脚本行为

```bash
cd testcase-generation-skills/src/scripts
node stage1/filter_requirement_doc.js --project-dir <工作区>
```

| 输出 | 说明 |
|------|------|
| `script/stage1/requirement_filtered.md` | 剔除后正文；含 HTML 注释声明 |
| `script/stage1/requirement_filter_report.json` | 被删章节列表 |

算法：按 Markdown `#` 标题或「一、」「1.1」标题切块；过滤标题命中后跳过直至同级/更高级标题。  
标题文本以「一、二、…」开头时一律视为章级 L1（即使写成 `## 二、…`），避免后续章节被吞进「需求背景」过滤子树。

---

## 四、1A 提取约束

1. **只读** `requirement_filtered.md` + 锁定 `test_context`  
2. `confirmed_points` 不得出现：以「现状问题」为题、或 detail 写「保留区 1.x 需求背景」  
3. 可测改动应写成 **期望行为**（如「降级超限时弹窗选择保留员工」），而非复述旧问题  
4. finalize 会对草稿做背景词审计；命中则告警，可配置为失败

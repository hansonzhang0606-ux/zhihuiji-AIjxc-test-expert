## 二、总原则

```text
少读、读对 → 结构化生成 → 写入既有阶段报告 / 校验失败 → 人审只裁业务歧义
```

| 层 | 做 | 不做 |
|----|----|------|
| 输入 | 过滤正文、锁定 C-CTX、唯一临时知识点、禁止旧 draft / 禁止读长期库全文 | 1A 读 `input/需求文档` 原文；Stage4 读临时知识点 |
| 生成 | 等价类、切片、标题模板（按类型） | 「请注意去重」类软提示当门禁 |
| 门禁 | 并入既有阶段报告字段；跨阶段可选一份 summary | 每阶段新建平行的 `quality_gate_report.json` |
| 人审 | 口径、联测边界、是否值得独立测 | 拖排序、删端副本、抠混写句 |

| 阶段 | 写入位置 |
|------|----------|

| 3A | 扩展现有 `merge_report`（或等价）记录 absorb、纯度、等价冲突 |
| 3B | 现有 `matrix_filter_report.json` |

| 可选 | 仅当人审需要一页总览时：`script/config/quality_gate_summary.json`（聚合，非每阶段必产） |

## 三、因果等价类（去重协议）

### 3.1 规范化键（实现优先放 draft / validator）

```text
canonical_key = hash(trigger, primary_object, condition, primary_outcome)
```

| 字段 | 含义（领域无关） |
|------|------------------|
| `trigger` | 操作或触发来源（多种等价触发可归一，见 §5.4） |
| `primary_object` | **主业务对象**（本条要验证谁） |
| `condition` | 关键前提/边界 |
| `primary_outcome` | **主可观察结果**（本条断言什么） |

- **同键** → 合并为一条（或一条主陈述 + detail），禁止双 confirmed / 双独立 TP/TC  
- **必须拆** → `primary_object` 不同，或 `primary_outcome` 不可互相蕴含  
- **初期不强制**给 C-RP / C-TP / C-TC 三份 schema 同步加字段；校验通过后再考虑最小必要字段进入 **C-TP**（Stage4 的排序/absorb 依赖处）

### 3.2 RP 分层

| 类型 | 用途 | 与 scenario 关系 |
|------|------|------------------|
| `rule` | 口径、公式、权限定义 | 可被某 scenario 完全蕴含 → 不进 confirmed，写入 detail 或 pending |
| `scenario` | 触发 × 条件 × 结果 | 同 `canonical_key` 只留一条 |

### 3.3 生成顺序

先抽候选键 → 合并 → 再写 RP/TP；finalize 比对冲突 → 失败或并入 pending，并记入该阶段既有报告。

## 四、场景切片与模块纯度（通用）

### 4.1 流程

```text
混合叙述
  → 按 primary_object 切 scene_slices
  → 每片单独归属 module_l1/l2（须 ∈ module_mapping）
  → 仅当必须验证「多对象协同」时 → 集成（或 mapping 内等价名）
```

### 4.2 通用拆分判据（正文规则）

| 判据 | 动作 |
|------|------|
| 一条陈述含 ≥2 个主业务对象，且各自有独立可观察结果 | 拆成多 slice / 多条 |
| 仅一个主对象的结果；其他对象只出现在前置或操作依赖里 | **不拆**；允许步骤提及依赖对象 |
| 必须在同一条里验证跨对象联动才成立 | 标集成；允许多对象出现在**主断言** |

版本降级等业务映射仅作附录样例，**不是**默认模块表。

### 4.3 模块纯度（只约束主断言）

| 允许 | 禁止（非集成） |
|------|----------------|
| `precondition` / `steps` 提及依赖对象（数据准备、入口） | `title` / `expected` / `primary_outcome` 同时断言多个主对象的最终效果 |
| 集成模块条写跨对象协同期望 | 用全文关键词扫描「提及即混写」导致误杀 |

机检对象：标题、期望要点、主断言字段；**不对步骤全文做混写关键词一票否决**。

## 五、临时知识点与分阶段 I/O

### 5.0 本需求临时知识点（唯一文件）

| 项 | 规格 |
|----|------|
| **唯一路径** | `script/stage1/domain_facts.json` |
| **禁止别名并行** | 不得同时把 `session_facts.json` / `kb_applied.json` 当作 Stage 输入；6.2 截取须**合并写入**本文件 |
| 来源 | `human_review`（人审澄清）；`kb_applied`（6.2 截取合并，可选） |
| 字段 | `statement`、`forbid_patterns[]`、`source`、`session_only`（bool） |
| **消费者** | **仅 1A、3A** 注入与校验 |
| **固化** | 3A 定稿时将可执行断言落入 C-TP（标题/期望/`steps_outline` 等）；之后以 C-TP 为准 |
| Stage4 | **禁止**再读本文件 |
| 可见性 | 人审①′/② 摘要可展示；非 `output/*.xmind` 主交付 |
| 禁止 | 6.1 写 `templates/kb/**`；把本文件当工程真源 |

`session_only=true`：仅本需求例外；默认不晋升 6.2（须显式「补充知识库」）。

### 5.1 Stage0 / 1CTX

| | 规格 |
|--|------|
| 输入 | 父页产品线、标题解析（沿用 6.0） |
| 输出 | `regression_hints` 可配置；默认不对「非本产品线 / 非本需求端」生成进 TP 的宽松 P3；或标 `auto_skip_tp=true` |
| 人审① | 确认三维 in/out 与回归策略 |

### 5.2 Stage1A

| | 规格 |
|--|------|
| 输入 | `requirement_filtered.md` + 锁定 C-CTX + `domain_facts.json`（若存在） |
| 禁止 | `input/需求文档` 原文；历史 draft；`templates/kb` 全文 |
| 生成 | 先 `canonical_key` 再 RP；rule/scenario 分层 |
| 门禁 | 背景词审计；同键重复失败 → 写入 1A 定稿/校验结果 |

### 5.3 Stage3 / 3A

| | 规格 |
|--|------|
| 输入 | C-RP、C-MOD、C-CTX、`domain_facts.json`（若存在） |
| 生成 | 原子化；覆盖临时知识点断言；可合并 vs 必须拆（§三、§四） |
| 门禁 | 悬空 RP 引用、模糊指代、同键多 TP；可标 `coverage_candidate=absorb` → 记入 `merge_report` |
| 回归 | `auto_skip_tp` 默认不生成 TP |
| 输出 | C-TP **已含**可执行期望；供 Stage4 单源消费 |

### 5.4 Stage4

| | 规格 |
|--|------|
| **唯一业务输入** | 已批准 C-TP（+ 既有排序/导出配置） |
| **禁止输入** | `domain_facts.json`、需求原文、长期 KB |
| 约束 | 端差异用 `platform_tags`，禁止同逻辑多端复制条；多触发默认归一为一种（可配置 `preferred_trigger`） |
| 裁剪 | `absorb` / 已被主路径步骤覆盖的不落独立 TC |
| 纯度 | 同 §4.3（只检标题/期望） |
| 标题 | **功能 / 状态 / 规则类**：倾向「条件，则结果」；**NFR**（`nfr_type` 非空）用各自模板，不强制因果句 |
| 排布 | §六；质量写入既有 Stage4 `quality_report` |

## 六、聚类与执行排布

```text
sort_key = module_l2 + primary_object_family + outcome_family + condition_family
```

- 生成后按 `sort_key` **稳定排序**再写 JSON/XMind  
- 可选在 C-TP/C-TC 增加 `cluster_key`（或仅导出前计算，不强制改 schema）  
- 排布是交付契约，不是美化选项

## 七、人审职责

| 应处理 | 不应反复处理 |
|--------|----------------|
| 临时知识点口径是否正确 | 拖拽排序 |
| 是否真正需要跨对象集成条 | 删除「同逻辑多端」副本 |
| 某计算是否值得独立测（absorb 争议） | 删除步骤已覆盖的纯触发条 |
| 门禁报告中的待裁决项 | 因步骤「提及」依赖对象而误判混写 |

晋升长期库 → 6.2「补充知识库」，不在 Fast Path 默认入库。

## 八、实现优先级

| 优先级 | 项 |
|--------|----|
| **P0** | 1A 背景审计 + `canonical_key` 去重（draft/validator） |
| **P0** | 场景切片通用判据 + **主断言**纯度；Stage4 只读 C-TP |
| **P0** | 唯一 `domain_facts.json`；仅 1A/3A 读 |
| **P1** | 端/触发不膨胀；absorb；回归收紧；功能类因果标题 + cluster 排序 |
| **P2** | 可选 `quality_gate_summary.json`；C-TP 最小字段固化 `canonical_key` / `cluster_key` |

**最小闭环：** 去重键（校验器）+ 主断言纯度 + Stage4 单源 + cluster 排序。  
长期库读取：**不在 6.1**，见 6.2。

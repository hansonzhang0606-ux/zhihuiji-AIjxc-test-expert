# 测试用例生成 Skill — 使用说明

这是进销存系统测试用例自动生成的说明（Fast Path）。Agent 编排入口：[`skill.md`](./skill.md)；阶段细则：[`src/stages/`](./src/stages/)。

> **v7.2.0 起**：套件已内嵌**时间节省追踪**（`src/scripts/time-tracking/`，业务线预置「AI进销存」）——
> 每个关键环节完成后，助手会强制请你反馈「这一步省了多少时间」，数据先记本地，再由定时任务同步到团队 MySQL。
> 详见文末「五、时间节省追踪」。

---

## 一、怎么开始用


### 1.1 在 Agent 里怎么说

**最常见的情况：丢一个 Confluence 链接，然后说「生成用例」**

比如：

https://finkms.kingdee.com/pages/viewpage.action?pageId=100655937 生成用例

就这一句话，Agent 就知道要干嘛了。

### 1.2 跑完你会拿到什么

东西都会落在 **testcase-generation-skills/output/** 下面：

- 标题以 `v4.6.0` / `V4.6.0` 开头 → 需求全部文件会放在版本目录下，例如 `output/v4.6.0/{需求标题}/`
- 标题没有版本号 → 需求全部文件会output目录下，例如 `output/{需求标题}/`
- **周迭代**（标题里带「周迭代」）→ 会拆成多个子需求，目录形如 `output/v4.6.0/v4.6.0_周迭代_{子需求名}/`，做完一个会问你要不要做下一个

你可以只关注每个需求文件夹下的“output”产物：
| 阶段完成后 | 对外文件（用 XMind 打开看） | 机器真源（Agent 实际改的是这里） |
|------------|------------------------------|----------------------------------|
| 需求点 | output/需求点_{标题}.xmind | script/stage1/requirement_points.json |
| 测试点 | output/测试点_{标题}.xmind | script/stage3/test_points.json |
| 测试用例 | output/测试用例_{标题}.xmind | script/stage4/test_cases.json |
| Stage5 平台 P0 | output/测试用例_P0_{标题}.xlsx | script/stage5/test_cases_P0_platform.xlsx |

如果需要 DevOps 平台导入，Stage5 导出 P0 Excel，见 [`stage5_platform_import.md`](./src/stages/stage5_platform_import.md)。Stage4 全量 Excel 默认在 `script/stage4/test_cases.xlsx`。

### 1.3 整体流程（中间要你确认 3～4 次）

下载需求 → 识别产品/版本/端  
    ↓  
⛔ 人审①  你确认：产品 / 版本 / 端对不对  →  ⏱ 反馈：文档整理省了多少时间  
    ↓  
生成需求点 XMind  
    ↓  
⛔ 人审①′ 你确认：需求点全不全、准不准  →  ⏱ 反馈：需求评审省了多少时间  
    ↓  
生成测试点 XMind  
    ↓  
⛔ 人审②  你确认：测试点是否 OK  →  ⏱ 反馈：生成测试点省了多少时间  
    ↓  
生成用例 XMind  
    ↓  
（可选）你预览用例，有改再说；说「可以了」就算交付  →  ⏱ 反馈：用例细化省了多少时间  
    ↓  
（可选）Stage5：导出 P0 Excel → DevOps 用例管理导入  →  ⏱ 反馈：导入归档省了多少时间

带 ⛔ 的地方，Agent **一定会停下来等你回复**，不会自己帮你点「通过」。
带 ⏱ 的地方，Agent 会**必填式**问你「这一步节省了多少时间」，可回「采纳」（用参考上限）或直接说「4小时」「0.5人天」。

## 二、中间怎么确认、怎么改

### 2.1 几条通用规矩（每个确认环节都一样）

1. **XMind 只能看，不能当改稿工具**——你在 XMind 里改了也不会生效。  
2. **改动都在对话里说**，Agent 会去改 JSON，然后重新导出 XMind。  
3. 可以 **反复改**；改满意了直接说 **「无需修改」** 或 **「可以了」** 就能进下一步。  
4. 改动少的话你直接列出来就行；改动多的话 Agent 会给你清单模板，你填一下。

### 2.2 人审① — 确认产品 / 版本 / 端

Agent 会给你看一张类似这样的表：

| 维度 | 本次涉及 | 不涉及 |
|------|----------|--------|
| 产品 | ailit | 智慧记AI进销存、智慧记… |
| 版本 | 开单版、单店版、多店版 | — |
| 端 | PC端、APP端 | 小程序端 |

**觉得没问题，就这么回：**

准确，继续。

**要改范围的话，举例：**

版本只要单店版和多店版；小程序端也要测。

---

### 2.3 人审①′ — 确认需求点（这一步比较重要）

Agent 会告诉你 output/需求点_{标题}.xmind 在哪，然后请你审需求点。

**先说清楚：** XMind **只能看**，改动要在对话里说；Agent 改的是 JSON，改完会重新导出 XMind。需求点 XMind 里

**需求点 ≤ 20 条（小需求）— 直接在对话里列举改动：**

无需修改

或者按下面格式说：

已经确认点：  
1、授权失败会跳转 url，但提示未登录；  
2、url 异常、网络异常等，加载失败直接提示 url 异常，不进行跳转，没有兜底；  
3、弹窗点击取消后弹窗直接关闭，无后续提示；

修改：  
1、RP-005：只同步手机号信息；改为通过 v1/thirdpart 接口传递 ticket 参数；

补充点：  
1、如果手机缓存清除，登录态失效，再次点击时会重复弹窗；

**需求点 > 20 条（大需求）— Agent 需要你提供改动清单模板，例如：**

【补充】缓存清除后登录态失效，再次点击会重复弹窗  
【修改】RP-005：同步方式改为 v1/thirdpart 传 ticket  
【删除】RP-008  
【待确认→已确认】RP-103：按产品结论保留  
【待确认→删除】RP-108：本期不做

改完 Agent 会重新导出 XMind；你还可以继续改，或者回 **「无需修改」** 进测试点阶段。

---

### 2.4 人审② — 确认测试点

Agent 会给你 output/测试点_{标题}.xmind，顺便摘要一下 P0/P1 数量、有没有「未匹配模块」之类。

**没问题：**

无需修改

**要改的话，举例：**

【修改】TP-003：优先级改为 P0；期望第 2 条改为「跳转失败停留在当前页并 Toast 提示」  
【补充】弱网环境下 H5 加载超时 30s 的异常路径  
【删除】TP-012

如果 Agent 提示 **存在未匹配模块**，得先处理（补模块映射或者改需求点/测试点），**不能**直接生成用例。

---

### 2.5 用例预览（Stage4 之后，可选）

生成 output/测试用例_{标题}.xmind 之后，还想改就说：

【修改】TC-003：步骤 2 期望改为「接口返回 401 时展示未登录提示，不跳转」  
【补充】ticket 过期后重复点击联登按钮的用例

满意了回：

无需修改

## 五、时间节省追踪（v7.2.0 内嵌）

**每个环节完成后，助手会强制问你「这一步节省了多少时间」**（必填，不反馈会追问；确实不想答就说「不填」，会记 0）。

| 环节 | 对应统计步骤 | 参考值 |
|------|------------|--------|
| 人审① 通过后（下载+上下文识别） | 01 文档整理 | 2~4 小时 |
| 人审①′ 通过后（需求点提取） | 02 需求评审 | 2~3 小时 |
| 人审② 通过后（测试点合成） | 04 生成测试点 | 3~5 小时 |
| 用例交付「可以了」后 | 06 用例细化 | 4~8 小时 |
| Stage5 平台导入完成后 | 07 知识入库 | 1~2 小时 |

怎么回答：回「**采纳**」（用参考上限）／「**4小时**」／「**0.5人天**」都行；助手会跟你二次确认后才记录。

- 首次使用会请你输入**姓名**（花名册验证）并登记**用户故事编号+名称**（如 `PRJ-00758363 优化分类下搜索商品逻辑`），同一需求后续环节自动复用，不用重复输入
- 数据**先记本地**，再由定时任务（每日 09:00 / 12:00 / 18:00）自动同步到团队共享数据库
- 想看自己/团队累计省了多少时间：说「**查看时间统计**」「**时间报告**」，会生成 HTML 报告并打开
- 首次使用时助手会生成一个 MySQL 配置模板文件让你本地填写（含密码，别发群、别提交 Git），填好回「已填好」即可

**双宿主一致**：WorkBuddy 里的「智慧记 AI 进销存专家」和 VSCode / OpenCode 等 IDE 里用的都是这一套，数据落到同一个数据库。

## 四、常见问题

| 问题 | 怎么处理 |
|------|----------|
| Confluence 拉不下来 | 把需求导出成 md，告诉 Agent 本地文件路径 |
| 只在 XMind 里改了 | 跟 Agent 再说一遍改动，以对话为准 |
| 只想看测试点、不要写用例 | 开头就说「只要测试点不要用例」（时间追踪也只记到测试点环节） |
| 改了三维（产品/版本/端） | 回到人审①，别只在需求点里硬改标签 |
| 测试点有「未匹配」 | 人审②不能点通过，先改映射或需求/测试点 |
| 不想反馈节省时间 | 直接说「不填」，助手记 0 并继续（每个环节都会问一次，这是效能统计的强制设计） |
| 换了一个需求/子需求 | 告诉 Agent 新的用户故事编号+名称，时间统计会跟着切换 |
